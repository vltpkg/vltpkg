Usage:

<Code code="$ vlt ci" title="Terminal" lang="bash" />

Clean install for CI pipelines. Removes `node_modules` and installs
dependencies exactly as specified in `vlt-lock.json`, failing if the
lockfile is missing or out of date.

## Lifecycle scripts

Like [`vlt install`](/client/commands/install), `vlt ci` runs **no
lifecycle scripts** of dependencies by default. To opt in:

<Code
  code={`# Allow scripts for specific packages, this run only
$ vlt ci --allow-scripts="#esbuild"

# Save the query as allow-scripts in vlt.json: vlt ci runs it

$ vlt build "#esbuild"

# Or build after install: the stored query, else the default (no TTY: not saved)

$ vlt ci && vlt build`} title="Terminal" lang="bash" />

See [`vlt build`](/client/commands/build#allow-scripts) for
`allow-scripts`.

## Workspaces

`vlt ci` reads workspaces from `vlt.json` only. If they are declared
only in `package.json` or `pnpm-workspace.yaml`, it warns and ignores
them: run `vlt install` and commit `vlt.json` (see
[Workspaces](/client/workspaces#saving-workspaces-to-vltjson)).

## Options

| Flag                      | Description                                                                                           |
| ------------------------- | ----------------------------------------------------------------------------------------------------- |
| `--allow-scripts=<query>` | Allow matching packages to run lifecycle scripts (never saved)                                        |
| `--allow-skills=<query>`  | Link the agent skills of matching packages (never saved), see [`vlt skills`](/client/commands/skills) |
| `--skills-dir=<path>`     | Dirs to link agent skills into, see [`vlt skills`](/client/commands/skills)                           |
