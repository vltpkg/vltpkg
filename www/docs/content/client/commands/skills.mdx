Usage:

<Code
  code="$ vlt skills [list|link|unlink] [<query>]"
  title="Terminal"
  lang="bash"
/>

Manage the agent skills shipped by your installed dependencies.

An agent skill is a folder with a `SKILL.md` file, as defined by the
[Agent Skills specification](https://agentskills.io/specification).
Packages can ship them alongside their code, and `vlt skills` links
them into your project so coding agents can find them.

## Where packages ship skills

`vlt` looks for skills inside each installed package at:

- `skills/<name>/SKILL.md` – one folder per skill, named `<name>`
- `SKILL.md` at the package root – a single skill, named after the
  `name` field of its frontmatter (or the package name, without its
  scope)

Only packages installed in the `node_modules/.vlt` store are scanned.
Workspaces and `file:` dependencies (folders and tarballs) are
skipped. One version of each package is used: the one the project
depends on directly, else the highest version, even if it ships no
skills.

When packages ship skills with the same name, one gets the link: the
package an existing link points to, while that skill is installed,
else a direct dependency, then the package id. The others are
reported. `vlt skills unlink <query>` frees a name. A fresh clone (no
links yet) may pick another package than a machine with older links.

## Layout

Each skill is linked at `./skills/<skill>`, named after the skill:

<Code
  code={`skills/
├── lint-rules -> ../node_modules/.vlt/~npm~foo@1.0.0/node_modules/foo/skills/lint-rules
├── migrate -> ../node_modules/.vlt/~npm~foo@1.0.0/node_modules/foo/skills/migrate
└── bar -> ../node_modules/.vlt/~npm~@scope+bar@2.0.0/node_modules/@scope/bar`}
  title="Layout"
  lang="text"
/>

On Windows, links are directory junctions. Junctions hold absolute
paths, so after moving or copying the project, run
`vlt skills link <query>` (or `vlt install` with `allow-skills` set)
to re-point them.

## Subcommands

### `list`

The default. Lists the skills of installed packages, marking the ones
already linked. Selects all packages (`*`) by default.

<Code
  code={`$ vlt skills
$ vlt skills list ":root > *"`}
  title="Terminal"
  lang="bash"
/>

### `link`

Links the skills of the selected packages, then removes skill links
whose skill is no longer installed: dangling, package removed, or no
longer shipped. Like [`vlt build`](/client/commands/build), selects
`:not(:malware)` by default.

<Code
  code={`# every package without malware alerts
$ vlt skills link
# a single package
$ vlt skills link "#my-package"`}
  title="Terminal"
  lang="bash"
/>

### `unlink`

Removes the skill links of the selected packages, plus any dangling
ones. Removes them all by default.

<Code
  code={`$ vlt skills unlink
$ vlt skills unlink "#my-package"`}
  title="Terminal"
  lang="bash"
/>

Select packages with a [DSS query](/client/selectors) after the
subcommand, or with `--target=<query>`, which wins over the positional
argument.

## Linking on install

`vlt install`, `vlt ci` and `vlt update` link no skills by default.
Use `--allow-skills` to link the skills of matching packages after a
successful install:

<Code
  code={`# link the skills of direct dependencies
$ vlt install --allow-skills=":root > *"
# persist it for every install
$ vlt config set "allow-skills=:root > *"`}
  title="Terminal"
  lang="bash"
/>

With `--allow-skills`, stale skill links are removed too, like
`vlt skills link`, and a link follows its package to a new version. An
invalid query fails before anything is installed. Narrowing
`--allow-skills` keeps links that still point to an installed package;
use `vlt skills unlink` to remove them.

`vlt install`, `vlt ci`, `vlt update` and `vlt uninstall` always
remove dangling skill links (package removed or at another version).
Without `--allow-skills`, a new version is not linked again: run
`vlt skills link <query>`.

## Safety

- `vlt` only ever replaces or removes links that point into a
  `node_modules/.vlt` store. Anything else at a link path (your own
  files, folders or links) is skipped and reported, never changed.
- Linked skills are views of installed package files: don't edit them,
  a reinstall replaces them. Files hardlinked from the global store
  get private copies when linked, so edits stay in this project.

## Ignoring linked skills in git

Skill links are generated by install, so ignore them while keeping any
skills your project publishes:

<Code
  code={`# .gitignore
/skills/*
!/skills/my-own-skill/`}
  title=".gitignore"
  lang="text"
/>

## Limits

- Skills are linked into `./skills` only.
- Skills nested deeper than `skills/<name>/SKILL.md` are not found.
