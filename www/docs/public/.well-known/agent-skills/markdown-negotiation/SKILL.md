# Markdown Content Negotiation

## Overview

This site supports markdown content negotiation for AI agents.
Documentation pages can be requested in markdown format using HTTP
Accept header negotiation.

## Usage

Send a request to any documentation page with the
`Accept: text/markdown` header:

```http
GET /get-started HTTP/1.1
Accept: text/markdown
```

The server will respond with the documentation converted to
GitHub-flavored markdown:

```http
HTTP/1.1 200 OK
Content-Type: text/markdown; charset=utf-8
Cache-Control: public, max-age=3600

# Installation

...markdown content...
```

## Supported Paths

- All documentation pages under `/docs/*`
- Excludes: API routes (`/api/*`), static assets, and other
  non-documentation pages

## API Endpoint

Markdown can also be requested directly, without content negotiation,
via the API route:

```http
GET /api/markdown/:slug
```

- `:slug` is the doc path relative to `src/content/docs` (e.g.
  `get-started/why-vlt` for `/docs/get-started/why-vlt`)
- Returns `200` with `Content-Type: text/markdown; charset=utf-8` on
  success
- Returns `400` if the slug is missing
- Returns `500` (with `Content-Type: text/markdown`) if conversion
  fails
- This is the endpoint the content-negotiation redirect and the
  copy-to-markdown button both call under the hood

## Response Format

- **Content-Type**: `text/markdown; charset=utf-8`
- **Format**: GitHub-flavored markdown (GFM) with:
  - Fenced code blocks with language tags
  - Tables
  - Strikethrough
  - Task lists
  - Proper heading hierarchy
  - Preserved links and images

## Caching

- Responses are cached for 1 hour
  (`Cache-Control: public, max-age=3600`)
- Agents can reduce load by respecting cache headers

## Error Handling

If markdown conversion fails for any reason:

- The server responds with HTTP 500 and `Content-Type: text/markdown`
- The response body contains the error message
- Agents can detect conversion failures by checking the HTTP status
  code

## How It Works

1. **Content Negotiation**: Requests to doc pages with
   `Accept: text/markdown` header are redirected to
   `/api/markdown/:slug`
2. **Slug Routing**: The API endpoint receives the doc slug (e.g.,
   `get-started/why-vlt`) and looks up the content
3. **Rendering**: The documentation is rendered to HTML using Astro's
   rendering engine with full support for React/MDX components
4. **Conversion**: The HTML is converted to GitHub-flavored markdown
   using Turndown

## Implementation Details

- Markdown is generated by rendering the documentation to HTML, then
  converting with Turndown
- Supports React components, MDX, and Astro content
- Preserves semantic structure from original HTML
- Removes navigation chrome, sidebars, and UI chrome
- API responses are cached for 1 hour to reduce server load

## Benefits for Agents

1. **Token Efficiency**: Markdown is more concise than HTML
2. **Semantic Clarity**: Structure is explicit (headings, lists, code
   blocks)
3. **Parsing Simplicity**: No DOM extraction needed
4. **Cache-Friendly**: Cacheable for repeated requests
