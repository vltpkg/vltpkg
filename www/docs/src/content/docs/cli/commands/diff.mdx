Show what changed between two states of a project.

## `vlt diff lockfile`

A raw `git diff` of `vlt-lock.json` is unreadable. The lockfile is a flat
map of dependency IDs, so a single transitive version bump — or a change
of registry — rewrites thousands of lines without saying anything about
what the dependency graph actually did.

`vlt diff lockfile` reads the lockfile from both sides, reconstructs the
dependency graph from each, and reports the changes as graph
operations: packages added and removed, versions upgraded and downgraded,
dependency edges retargeted.

### Choosing the two sides

With no arguments, the working tree is compared against `HEAD`:

<Code code="$ vlt diff lockfile" title="Terminal" lang="bash" />

With one argument, the working tree is compared against that ref:

<Code code="$ vlt diff lockfile main" title="Terminal" lang="bash" />

With two, they are compared to each other. `a..b` means the same as
`a b`:

<Code
  code="$ vlt diff lockfile main feat/my-branch
$ vlt diff lockfile main..feat/my-branch
"
  title="Terminal"
  lang="bash"
/>

`--base` and `--head` do the same job as the positional arguments, and
take precedence over them. Passing both a positional and its flag with
different values is an error rather than a silent override.

Either side may be a path to a lockfile on disk instead of a git ref.
Anything ending in `.json` is read as a path:

<Code
  code="$ vlt diff lockfile --base=./old/vlt-lock.json"
  title="Terminal"
  lang="bash"
/>

A ref that has no lockfile at all compares as an empty one, so the commit
that introduced the lockfile diffs cleanly rather than failing.

### The viewer

In a terminal, the human view takes over the window and narrows in four
steps, so a review is a sequence of small trees rather than one long
list:

<Code
  code="summary       the numbers, what is not routine, and the workspaces
  ↓
workspace     the dependency trees that changed inside it
  ↓
tree          one direct dependency and everything under it
  ↓
package       one change in full"
  title="Screens"
  lang="text"
/>

A tree lives in one workspace but its packages are usually shared, so
each one reports how far it reaches. Press `w` on a tree to list the
workspaces it actually lands on, and `n` / `p` to step between trees
without going back up.

The summary leads with the changes that are not a routine version bump,
each under a heading that names exactly what it holds — a section that
is empty is one you never have to read:

<Code
  code="LOCKFILE DIFF                                    263 changes
+50 packages    +304 edges    65 identity-only

4 MAJOR VERSIONS
   ▲  c8                 10.1.3 → 12.0.0   41 workspaces
   ▲  yargs              17.7.3 → 18.1.0   www/docs

1 REMOVED
   -  require-directory  2.1.1             www/docs

43 WORKSPACES
   www/docs              151
   src/cli-sdk            51"
  title="Summary"
  lang="text"
/>

Counts read as deltas, the way a `git diff` stat does, and the
workspaces are the real ones — a change that reaches forty of them is
counted for all forty, because "does this affect me" is the question
being asked.

A tree is drawn as one. Packages on the route that did not themselves
change are dimmed and shown for context, so the shape has no holes:

<Code
  code="1/28 vite                                        www/docs
 · vite
 └─ ↑ rollup  4.62.2 → 4.62.4
    ├─ + @napi-rs/lzma-linux-x64-gnu 1.5.1
    ├─ ↑ @rollup/rollup-darwin-arm64  4.62.2 → 4.62.4
    └─ ↑ @rollup/rollup-linux-x64-gnu  4.62.2 → 4.62.4"
  title="Tree"
  lang="text"
/>

Press `?` for a legend of every symbol.

<Code
  code="↑↓ / jk   move
⏎  / →    narrow to what is under the cursor
←  / esc  back a level
n / p     step to the next or previous tree
w         which workspaces this tree reaches
d         direct dependencies only
i         show the hidden changes (see below)
?         legend
q         quit
"
  title="Keys"
  lang="text"
/>

The viewer runs in the terminal's alternate screen, so quitting restores
your scrollback exactly as it was. In CI, when output is redirected, or
with `--no-tui`, the same diff is printed as static text instead.

### Severity

A version bump carries how far it moved, so a major bump is never
mistaken for a patch:

<Code
  code="^^ yargs   17.7.3 -> 18.1.0   major
^  prettier  3.9.5 -> 3.9.6
v  some-pkg  2.0.0 -> 1.9.0"
  title="Terminal"
  lang="text"
/>

In JSON this is `severity` on each `package-resolved` mutation:
`major`, `minor`, `patch`, `prerelease`, or `unknown` when either side
has no parseable version. It is independent of `direction` — a downgrade
can be major.

### JSON

<Code
  code="$ vlt diff lockfile origin/main --view=json"
  title="Terminal"
  lang="bash"
/>

The JSON view is the stable contract, carrying a `schemaVersion`, the
summary, every mutation, and the regions. Editors, CI annotations, and
other viewers should build against it rather than parsing lockfiles
themselves.

### Exit status

The exit status is always `0` unless `--exit-code` is given, in which
case it is `1` when anything changed:

<Code
  code="$ vlt diff lockfile origin/main --exit-code"
  title="Terminal"
  lang="bash"
/>

## Reserved

Bare `vlt diff`, and the npm-compatible `--diff=<spec>` grammar for
diffing package *contents*, are reserved and not yet implemented. In this
release they print usage naming `vlt diff lockfile`.
