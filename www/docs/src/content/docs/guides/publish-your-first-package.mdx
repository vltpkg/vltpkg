You may have a component or function library to share at work, or you
simply want to keep a tool you wrote offline. Here's how to do that
using the vlt registry.

In this tutorial, we'll walk through publishing a simple TypeScript
package step by step using the
[hello-vlt starter](https://github.com/vltpkg/hello-vlt).

## Before you begin

You'll need:

- A vlt account. If you don't have one yet,
  [sign up here](https://registry.vlt.io).
- Node.js 18 or later
- Your preferred package manager installed (vlt, npm, pnpm, yarn, bun,
  or deno)

You can follow along this tutorial using our
["hello-vlt" starter](https://github.com/vltpkg/hello-vlt), or apply
these steps to your own package.

## Step 1: Clone the starter

<Code
  code="$ git clone https://github.com/vltpkg/hello-vlt my-package\n$ cd my-package"
  title="Terminal"
  lang="bash"
/>

(Replace `my-package` with your desired directory name.)

This starter is a minimal TypeScript package that exports a simple
function:

<Code
  code={`export function helloWorld(): string {
  return "Hello, World!";
}`}
  title="index.ts"
  lang="typescript"
/>

## Step 2: Update the package name and author

The `package.json` defines your package's metadata. Update it to match
your account:

<Tabs>
  <TabItem label="1. Change the name">
    Replace `hello-vlt` with `@YOUR-ACCOUNT/hello-vlt`:

    <Code
      code={`{

"name": "@YOUR-ACCOUNT/hello-vlt", "version": "1.0.0", "description":
"Hello World package", ... }`} title="package.json" lang="json" />

    (Replace `YOUR-ACCOUNT` with your vlt account slug — you can find this on your
    [account settings page](https://registry.vlt.io/account).)

  </TabItem>
  <TabItem label="2. Update the version">
    Reset to `1.0.0` to mark this as your first release:

    <Code
      code={`{

"name": "@YOUR-ACCOUNT/hello-vlt", "version": "1.0.0", ... }`}
title="package.json" lang="json" />

  </TabItem>
  <TabItem label="3. Update the author">
    <Code
      code={`{
  "author": {
    "name": "Your Name",
    "email": "your-email@example.com"
  },
  ...
}`}
      title="package.json"
      lang="json"
    />
  </TabItem>
</Tabs>

## Step 3: Configure your registry

Map your account scope to the vlt registry so your package manager
knows where to publish. Replace `YOUR-ACCOUNT` with your vlt account
slug.

<Tabs syncKey="pkg-manager">
  <TabItem label="vlt">
    <Code
      code="$ vlt config set scoped-registries=@YOUR-ACCOUNT=https://registry.vlt.io/YOUR-ACCOUNT/main/"
      title="Terminal"
      lang="bash"
    />

    This updates `vlt.json` with the registry mapping. Your `vlt.json` will now contain:

    <Code
      code={`{
  "config": {
    "scoped-registries": {
      "@YOUR-ACCOUNT": "https://registry.vlt.io/YOUR-ACCOUNT/main/"
    }
  }
}`}
      title="vlt.json"
      lang="json"
    />

    <Aside type="tip">
      When you run `vlt install` or other vlt commands, a `vlt-lock.json` file is
      created to lock dependency versions. Both `vlt.json` and `vlt-lock.json` should
      be committed to version control.
    </Aside>

  </TabItem>
  <TabItem label="npm">
    <Code
      code="$ npm config set @YOUR-ACCOUNT:registry https://registry.vlt.io/YOUR-ACCOUNT/main/ --location=project"
      title="Terminal"
      lang="bash"
    />

    This updates `.npmrc` with the scoped registry.

  </TabItem>
  <TabItem label="pnpm">
    <Code
      code="$ pnpm config set @YOUR-ACCOUNT:registry https://registry.vlt.io/YOUR-ACCOUNT/main/ --location=project"
      title="Terminal"
      lang="bash"
    />

    This updates `.npmrc` with the scoped registry.

  </TabItem>
  <TabItem label="yarn">
    <Code
      code={`yarn config set npmScopes.YOUR-ACCOUNT.npmRegistryServer "https://registry.vlt.io/YOUR-ACCOUNT/main/"
yarn config set npmScopes.YOUR-ACCOUNT.npmPublishRegistry "https://registry.vlt.io/YOUR-ACCOUNT/main/"`}
      title="Terminal"
      lang="bash"
    />

    This updates `.yarnrc.yml` with the scoped registry.

  </TabItem>
  <TabItem label="bun">
    <Code
      code={`# Edit or create bunfig.toml and add:
[install.scopes.YOUR-ACCOUNT]
url = "https://registry.vlt.io/YOUR-ACCOUNT/main/"
token = "$VLT_TOKEN"`}
      title="bunfig.toml"
      lang="toml"
    />
  </TabItem>
  <TabItem label="deno">
    <Code
      code={`cat >> .npmrc <<'EOF'
@YOUR-ACCOUNT:registry=https://registry.vlt.io/YOUR-ACCOUNT/main/
//registry.vlt.io/YOUR-ACCOUNT/main/:_authToken=\${VLT_TOKEN}
EOF`}
      title="Terminal"
      lang="bash"
    />
  </TabItem>
</Tabs>

## Step 4: Authenticate

Before you can publish, you need to authenticate with the vlt
registry:

<Tabs syncKey="pkg-manager">
  <TabItem label="vlt">
    <Code code="$ vlt login --registry=https://registry.vlt.io/YOUR-ACCOUNT/main/" title="Terminal" lang="bash" />

    This opens your browser to log in. Once authenticated, your credentials are
    stored locally for future publishes.

  </TabItem>
  <TabItem label="npm">
    <Code
      code="$ npm login --registry=https://registry.vlt.io/YOUR-ACCOUNT/main/ --scope=@YOUR-ACCOUNT"
      title="Terminal"
      lang="bash"
    />

    This prompts you to enter your vlt credentials.

  </TabItem>
  <TabItem label="pnpm">
    <Code
      code="$ pnpm login --registry=https://registry.vlt.io/YOUR-ACCOUNT/main/ --scope=@YOUR-ACCOUNT"
      title="Terminal"
      lang="bash"
    />

    This will prompt you to enter your vlt credentials.

  </TabItem>
  <TabItem label="yarn">
    <Code
      code="$ yarn npm login --scope YOUR-ACCOUNT --always-auth --web-login"
      title="Terminal"
      lang="bash"
    />

    This opens your browser to log in.

  </TabItem>
  <TabItem label="bun">
    Create a personal token on your [account tokens page](https://registry.vlt.io/tokens)
    and set it as an environment variable:

    <Code code="$ export VLT_TOKEN=<your-token>" title="Terminal" lang="bash" />

    (Or add it to `.env` in your project.)

  </TabItem>
  <TabItem label="deno">
    Create a personal token on your [account tokens page](https://registry.vlt.io/tokens)
    and add it to a `.env` file (make sure it's in `.gitignore`):

    <Code code="$ echo 'VLT_TOKEN=<your-token>' >> .env" title="Terminal" lang="bash" />

    Pass `--env-file` when installing dependencies later.

  </TabItem>
</Tabs>

## Step 5: Build your package

The starter includes TypeScript, so build it before publishing:

<Tabs syncKey="pkg-manager">
  <TabItem label="vlt">
    <Code code="$ vlt run build" title="Terminal" lang="bash" />
  </TabItem>
  <TabItem label="npm">
    <Code code="$ npm run build" title="Terminal" lang="bash" />
  </TabItem>
  <TabItem label="pnpm">
    <Code code="$ pnpm run build" title="Terminal" lang="bash" />
  </TabItem>
  <TabItem label="yarn">
    <Code code="$ yarn build" title="Terminal" lang="bash" />
  </TabItem>
  <TabItem label="bun">
    <Code code="$ bun run build" title="Terminal" lang="bash" />
  </TabItem>
  <TabItem label="deno">
    <Aside type="note">
      The starter uses TypeScript, but Deno loads TypeScript natively,
      so you may not need a separate build step depending on your
      setup.
    </Aside>
  </TabItem>
</Tabs>

This compiles the TypeScript to JavaScript in the `dist/` directory,
which is what users will actually install.

## Step 6: Publish

Now you're ready to publish:

<Tabs syncKey="pkg-manager">
  <TabItem label="vlt">
    <Code code="$ vlt publish" title="Terminal" lang="bash" />
  </TabItem>
  <TabItem label="npm">
    <Code code="$ npm publish" title="Terminal" lang="bash" />
  </TabItem>
  <TabItem label="pnpm">
    <Code code="$ pnpm publish" title="Terminal" lang="bash" />
  </TabItem>
  <TabItem label="yarn">
    <Code code="$ yarn npm publish" title="Terminal" lang="bash" />
  </TabItem>
  <TabItem label="bun">
    <Code code="$ bun publish" title="Terminal" lang="bash" />
  </TabItem>
  <TabItem label="deno">
    <Aside type="caution">
      Deno does not support publishing to npm registries directly.
      You'll need to use a different tool (like `npm publish` or `pnpm
      publish`) to publish your package.
    </Aside>
  </TabItem>
</Tabs>

The registry validates your package and displays a confirmation with
the published version and scope. Your package is now live!

## What happens next

Your package is published to your private registry. Other members of
your account can install it with:

<Code
  code="$ vlt add @YOUR-ACCOUNT/hello-vlt"
  title="Terminal"
  lang="bash"
/>

To make your package publicly visible, you can change its visibility
in your [account settings](https://registry.vlt.io/account).

## Troubleshooting

### 403 Forbidden error

The package name must be scoped to your account (e.g.,
`@YOUR-ACCOUNT/hello-vlt`). Check your `package.json` and make sure the
scope matches your account slug.

### Authentication required

Run `vlt auth login` to authenticate, or set a `VLT_TOKEN` environment
variable with a personal token from your account settings.

### Version conflict

Each version can only be published once. If you get a conflict error, bump
the version in `package.json` and try again.
