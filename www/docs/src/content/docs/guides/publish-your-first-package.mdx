You may have a component or function library to share at work, or you
simply want to keep a tool you wrote offline. Here's how to do that
using the vlt registry.

In this tutorial, we'll walk through publishing a simple TypeScript package
step by step using the [hello-vlt starter](https://github.com/vltpkg/hello-vlt).

## Before you begin

This guide walks through publishing with **vlt**. If you're using npm, pnpm, or
another package manager, the registry and authentication steps are the same, but
the commands differ.

You'll need:

- A vlt account. If you don't have one yet, [sign up here](https://registry.vlt.io).
- Node.js 18 or later
- The vlt CLI installed on your machine (`npm install -g vlt`)

You can follow along this tutorial using our
["hello-vlt" starter](https://github.com/vltpkg/hello-vlt), or apply these
steps to your own package.

## Step 1: Clone the starter

<Code code="$ git clone https://github.com/vltpkg/hello-vlt my-package\n$ cd my-package" title="Terminal" lang="bash" />

(Replace `my-package` with your desired directory name.)

This starter is a minimal TypeScript package that exports a simple function:

<Code
  code={`export function helloWorld(): string {
  return "Hello, World!";
}`}
  title="index.ts"
  lang="typescript"
/>

## Step 2: Update the package name and author

The `package.json` defines your package's metadata. Update it to match your account:

<Tabs>
  <TabItem label="1. Change the name">
    Replace `hello-vlt` with `@YOUR-ACCOUNT/hello-vlt`:

    <Code
      code={`{
  "name": "@YOUR-ACCOUNT/hello-vlt",
  "version": "1.0.0",
  "description": "Hello World package",
  ...
}`}
      title="package.json"
      lang="json"
    />

    (Replace `YOUR-ACCOUNT` with your vlt account slug — you can find this on your
    [account settings page](https://registry.vlt.io/account).)
  </TabItem>
  <TabItem label="2. Update the version">
    Reset to `1.0.0` to mark this as your first release:

    <Code
      code={`{
  "name": "@YOUR-ACCOUNT/hello-vlt",
  "version": "1.0.0",
  ...
}`}
      title="package.json"
      lang="json"
    />
  </TabItem>
  <TabItem label="3. Update the author">
    <Code
      code={`{
  "author": {
    "name": "Your Name",
    "email": "your-email@example.com"
  },
  ...
}`}
      title="package.json"
      lang="json"
    />
  </TabItem>
</Tabs>

## Step 3: Configure your registry

Map your account scope to the vlt registry so `vlt` knows where to publish:

<Code
  code="$ vlt config set scoped-registries=@YOUR-ACCOUNT=https://registry.vlt.io/YOUR-ACCOUNT/main/"
  title="Terminal"
  lang="bash"
/>

This command updates `vlt.json` in your project with the registry mapping.

## Step 4: Authenticate

Before you can publish, you need to authenticate with the vlt registry:

<Code code="$ vlt auth login" title="Terminal" lang="bash" />

This opens your browser to log in. Once authenticated, your credentials are
stored locally so future publishes work without re-authenticating.

<Aside type="tip">
  If you prefer not to open a browser, you can generate a personal token on your
  [account settings page](https://registry.vlt.io/account) and set the
  `VLT_TOKEN` environment variable instead.
</Aside>

## Step 5: Build your package

The starter includes TypeScript, so build it before publishing:

<Code code="$ vlt run build" title="Terminal" lang="bash" />

This compiles the TypeScript to JavaScript in the `dist/` directory, which is
what users will actually install.

## Step 6: Publish

Now you're ready to publish:

<Code code="$ vlt publish" title="Terminal" lang="bash" />

The registry validates your package and displays a confirmation with the
published version and scope. Your package is now live!

## What happens next

Your package is published to your private registry. Other members of your account
can install it with:

<Code
  code="$ vlt add @YOUR-ACCOUNT/hello-vlt"
  title="Terminal"
  lang="bash"
/>

To make your package publicly visible, you can change its visibility in your
[account settings](https://registry.vlt.io/account).

## Troubleshooting

<Tabs>
  <TabItem label="403 Forbidden error">
    The package name must be scoped to your account (e.g., `@YOUR-ACCOUNT/hello-vlt`).
    Check your `package.json` and make sure the scope matches your account slug.
  </TabItem>
  <TabItem label="Authentication required">
    Run `vlt auth login` to authenticate, or set a `VLT_TOKEN` environment variable
    with a personal token from your account settings.
  </TabItem>
  <TabItem label="Version conflict">
    Each version can only be published once. If you get a conflict error, bump
    the version in `package.json` and try again.
  </TabItem>
</Tabs>
