You may have a component or function library to share at work, or you
simply want to keep a tool you wrote offline. Here's how to do that
using the vlt registry.

In this tutorial, we'll walk through publishing a simple TypeScript
package step by step using one of our
[starter examples](https://github.com/vltpkg/package-examples) for
your package manager.

## Before you begin

You'll need:

- A vlt account. If you don't have one yet,
  [sign up here](https://www.vlt.io/sign-up).
- Node.js 18 or later
- Your preferred package manager installed (vlt, npm, pnpm, yarn, bun,
  or deno)

You can follow along this tutorial using one of our starter examples
from the
[package-examples](https://github.com/vltpkg/package-examples)
repository, or apply these steps to your own package.

## Step 2: Update the package name and author

Edit `package.json` and make these changes:

1. **Change the name** to `@YOUR-ACCOUNT/my-package`

   Replace `YOUR-ACCOUNT` with your vlt account slug (find it on your
   [account settings page](https://registry.vlt.io/account)). You can
   use any name for `my-package`.

2. **Update the version** to `1.0.0` to mark this as your first
   release

3. **Update the author** with your information

Here's the complete updated `package.json`:

<Code
  code={`{
  "name": "@YOUR-ACCOUNT/my-package",
  "version": "1.0.0",
  "description": "My awesome package",
  "main": "dist/index.js",
  "types": "dist/index.d.ts",
  "author": {
    "name": "Your Name",
    "email": "your-email@example.com"
  },
  ...
}`}
  title="package.json"
  lang="json"
/>

## Step 3: Configure your registry

Map your account scope to the vlt registry so your package manager
knows where to publish. Replace `YOUR-ACCOUNT` with your vlt account
slug.

<Tabs syncKey="pkg-manager">
  <TabItem label="vlt">
    <Code
      code="vlt config set scoped-registries=@YOUR-ACCOUNT=https://registry.vlt.io/YOUR-ACCOUNT/main/"
      title="Terminal"
      lang="bash"
    />

    This updates `vlt.json` with the registry mapping. Your `vlt.json` will now contain:

    <Code
      code={`{

"config": { "scoped-registries": { "@YOUR-ACCOUNT":
"<https://registry.vlt.io/YOUR-ACCOUNT/main/>" } } }`}
title="vlt.json" lang="json" />

    <Aside type="tip">
      When you run `vlt install` or other vlt commands, a `vlt-lock.json` file is
      created to lock dependency versions. Both `vlt.json` and `vlt-lock.json` should
      be committed to version control.
    </Aside>

  </TabItem>
  <TabItem label="npm">
    <Code
      code="npm config set @YOUR-ACCOUNT:registry https://registry.vlt.io/YOUR-ACCOUNT/main/ --location=project"
      title="Terminal"
      lang="bash"
    />

    This updates `.npmrc` with the scoped registry.

  </TabItem>
  <TabItem label="pnpm">
    <Code
      code="$ pnpm config set @YOUR-ACCOUNT:registry https://registry.vlt.io/YOUR-ACCOUNT/main/ --location=project"
      title="Terminal"
      lang="bash"
    />

    This updates `.npmrc` with the scoped registry.

  </TabItem>
  <TabItem label="yarn">
    <Code
      code={`yarn config set npmScopes.YOUR-ACCOUNT.npmRegistryServer "https://registry.vlt.io/YOUR-ACCOUNT/main/"
yarn config set npmScopes.YOUR-ACCOUNT.npmPublishRegistry "https://registry.vlt.io/YOUR-ACCOUNT/main/"`}
      title="Terminal"
      lang="bash"
    />

    This updates `.yarnrc.yml` with the scoped registry.

  </TabItem>
  <TabItem label="bun">
    <Code
      code={`# Edit or create bunfig.toml and add:
[install.scopes.YOUR-ACCOUNT]
url = "https://registry.vlt.io/YOUR-ACCOUNT/main/"

      title="bunfig.toml"

    />
  </TabItem>

## Step 5: Authenticate

Before you can publish, you need to authenticate with the vlt
registry:

<Tabs syncKey="pkg-manager">
  <TabItem label="vlt">
    <Code code="$ vlt login --registry=https://registry.vlt.io/YOUR-ACCOUNT/main/" title="Terminal" lang="bash" />

    This opens your browser to log in. Once authenticated, your credentials are
    stored locally for future publishes.

  </TabItem>
  <TabItem label="npm">
    <Code
      code="$ npm login --registry=https://registry.vlt.io/YOUR-ACCOUNT/main/ --scope=@YOUR-ACCOUNT"
      title="Terminal"
      lang="bash"
    />

    This prompts you to enter your vlt credentials.

  </TabItem>
  <TabItem label="pnpm">
    <Code
      code="$ pnpm login --registry=https://registry.vlt.io/YOUR-ACCOUNT/main/ --scope=@YOUR-ACCOUNT"
      title="Terminal"
      lang="bash"
    />

    This will prompt you to enter your vlt credentials.

  </TabItem>
  <TabItem label="yarn">
    <Code
      code="$ yarn npm login --scope YOUR-ACCOUNT --always-auth --web-login"
      title="Terminal"
      lang="bash"
    />

    This opens your browser to log in.

  </TabItem>
  <TabItem label="bun">
    Create a personal token on your [account tokens page](https://registry.vlt.io/tokens)
    and set it as an environment variable:

    <Code code="$ export VLT_TOKEN=<your-token>" title="Terminal" lang="bash" />

    (Or add it to `.env` in your project.)

  </TabItem>
  <TabItem label="deno">
    Create a personal token on your [account tokens page](https://registry.vlt.io/tokens)
    and add it to a `.env` file (make sure it's in `.gitignore`):

    <Code code="$ echo 'VLT_TOKEN=<your-token>' >> .env" title="Terminal" lang="bash" />

    Pass `--env-file` when installing dependencies later.

  </TabItem>
</Tabs>

The registry validates your package and displays a confirmation with
the published version and scope. Your package is now live!

## What happens next

Your package is published to your private registry. Other members of
your account can install it with:

<Code
  code="$ vlt add @YOUR-ACCOUNT/hello-vlt"
  title="Terminal"
  lang="bash"
/>

To make your package publicly visible, you can change its visibility
in your [account settings](https://registry.vlt.io/account).

## Troubleshooting

### 403 Forbidden error

The package name must be scoped to your account (e.g.,
`@YOUR-ACCOUNT/hello-vlt`). Check your `package.json` and make sure
the scope matches your account slug.

### Authentication required

Run `vlt auth login` to authenticate, or set a `VLT_TOKEN` environment
variable with a personal token from your account settings.

### Version conflict

Each version can only be published once. If you get a conflict error,
bump the version in `package.json` and try again.

### Config Error: Missing registry configuration

If you're using vlt and see this error when running `vlt install`, it
means vlt needs a default registry configured for downloading
dependencies. You have two options:

1. **Use npm instead** (simpler for dependency installation):

   ```bash
   npm install
   ```

   npm will download dependencies from the public npm registry, while
   `vlt publish` will still use your scoped registry configuration.

2. **Configure a default registry** (if you want vlt to manage all
   packages):

   ```bash
   vlt config set registry=https://registry.vlt.io/YOUR-ACCOUNT/npm/
   ```

   Then run `vlt install` to download dependencies through your vlt
   mirror.

For most users, option 1 is simpler — you only need the scoped
registry configured for publishing your own packages.
